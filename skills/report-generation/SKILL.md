# Report Generation

## 目标

将已经取得并分析的数据转化为结构清楚、证据充分、易于阅读并能支持下一步决策的 Markdown 报告。报告应突出重要信息，同时保留足以正确理解结论的数据来源、统计口径和限制。

## 适用条件

- 用户要求撰写、完善或整理分析报告、管理简报或结果摘要。
- 已有分析结果、指标和结论，需要面向业务人员、管理者或分析人员交付。
- 多个发现、表格或图表需要组织成统一叙事。
- 用户提供了分析材料，需要压缩冗余并提高表达清晰度。

只有原始数据、尚未完成分析时，使用 `data-analysis`。还需要从数据库发现数据或执行查询时，可按需加载 `database-exploration`。已有材料足够时，不必为了形式完整加载其他 Skill。

## 职责边界

本 Skill 负责选择和组织已有分析结果、解释表达、图表规划和 Markdown 报告写作。它不重新承担 `data-analysis` 的指标计算、数据质量分析、假设验证和洞察发现职责，也不负责寻找数据库或重新执行完整取数流程。

报告阶段发现关键证据不足、数字矛盾或口径不明时，应指出具体缺失，并请求补充分析或按需加载相应 Skill；不得自行推导新的业务事实来填补空白。

Markdown 正文可以直接生成。实际图表、文件导出或报告保存只有在当前会话存在对应 Tool 并实际执行成功时才能声称已经完成。没有图表 Tool 时，只能提供图表规划或基于真实结果制作 Markdown 表格；没有导出 Tool 时，只输出报告正文，不声称已保存文件。

当 `generate_chart` 可用且用户确实需要图表或正式报告时，可以调用它生成真实 PNG 图表。该工具的 `series` 是类别分组维度：例如 `x=month`、`y=sales`、`series=region` 表示每个地区生成一条折线。聚合、排序、Top N 和“其他”类别必须在 SQL 中完成；不得要求图表工具自行求和、平均或去重。同一个 `x` 和 `series` 组合存在多条记录时，应先修正 SQL。

只有 `generate_chart` 成功返回 artifact 后，才能把返回的 `markdown` 或 `url` 写入报告。不得自行编造 artifact 地址，也不得把失败、过期或未实际生成的图表描述为已完成。图表 artifact 是临时交付物，正式长期保存需要产品侧另行提供持久化能力。

## 核心规则

1. 每项关键数字和事实性结论都必须能追溯到已有 Tool Result、用户提供的数据或已完成的分析结果。
2. 不为填满章节而编造数字、原因、图表、业务影响或建议依据。
3. 优先呈现与用户目标和读者决策相关的信息，不按工具调用或分析操作顺序写流水账。
4. 明确区分事实、观察、解释、假设和建议；不得把观察写成普遍规律，把假设写成事实，或把相关关系写成因果关系。
5. 重要指标应尽可能说明数据来源、统计范围、时间范围、单位、筛选条件、对比基准和统计口径。不要求把全部 SQL 展示在报告正文中。
6. 证据不足时降低结论强度、标记限制或省略结论，不通过报告措辞掩盖不确定性。
7. 图表必须回答具体问题并与实际数据一致，不能用于装饰、重复正文或制造夸张视觉效果。
8. 建议必须关联已有发现，并说明适用范围；不得承诺没有证据支持的收益。

## 报告类型与深度

以下形式不是互斥的固定分类。根据用户目标、目标读者、任务复杂度、材料完整程度和交付要求选择最小但足够的报告深度，不要求机械套用固定模板。

### 简短结果摘要

适用于单个事实、简单统计、排名或明确问题。直接给出结果、必要口径和重要限制，不强制加入执行摘要、方法、建议和图表章节。

### 管理层简报

适用于管理者快速了解结果并做出行动判断。优先呈现少量核心发现、业务影响、建议行动和主要风险；减少技术细节，但不得省略会改变结论理解的口径和限制。

### 对比或趋势报告

适用于类别、群体、地区或时间段之间的比较。明确比较对象、指标、基准、时间粒度和变化幅度，区分绝对量与比例，并说明基数或口径变化。

### 探索性分析报告

适用于整理多项发现、异常和候选解释。明确区分已验证事实、数据观察和待验证假设；报告可以提出后续分析方向，但不得把探索性线索包装成确定结论。

### 正式数据分析报告

适用于材料完整、需要正式交付的复杂任务。可包含执行摘要、目标与范围、数据与方法、关键指标、核心发现、分项分析、图表、建议、风险与限制、后续工作和附录。只保留与报告主线相关的章节。

## 报告输入完整性检查

生成报告前，检查：

- 分析目标和需要回答的问题是否明确。
- 目标读者、使用场景或需要支持的决策是否明确；如果不明确，可采用与用户请求相称的通用表达，不必为简单任务反复追问。
- 数据来源、数据范围和必要的时间范围是否明确。
- 核心指标、单位、过滤条件、分母和统计口径是否明确。
- 是否存在实际查询、计算或用户提供的真实结果。
- 现有证据是否足以支持核心结论。
- 会影响结论的数据质量、样本、方法和工具限制是否已知。

根据材料完整程度选择交付状态：

- **正式报告**：目标、核心口径、关键结果和主要限制足以支撑结论。
- **初步报告或报告草案**：已有部分可靠结果，但仍缺少非关键材料，或部分结论只能作为观察和假设。
- **需要补充分析**：缺少会直接影响核心结论的查询结果、指标口径、数据范围或验证。明确列出缺少什么以及为什么影响报告，不生成伪完整报告。

不要求所有报告都具备同等材料。简单结果摘要只需具备回答当前问题所需的最小证据。

## Tool Result 与数据限制

使用 DataPilot 工具结果前，应检查其完整性和限制，而不是只读取 `rows`。

### execute_readonly_sql

- 检查 `truncated` 和 `truncationReasons`。
- `ROW_LIMIT` 表示返回行数达到上限；返回明细不能代表完整总体，也不能直接用于完整排名、类别总数或总体分布。
- `RESULT_SIZE_LIMIT` 表示部分行或列可能因整体结果大小限制未返回；只能使用明确仍然完整的内容。
- `FIELD_LENGTH_LIMIT` 表示至少一个长文本或二进制字段被缩短。它通常不影响同一结果中完整的数值指标，但被截断字段不能用于完整文本分析。
- 被截断的结果不应一概作废。若返回的是数据库已经完成的单行聚合，并且聚合值本身完整，可以使用该聚合结果；若截断影响了分组行、明细覆盖或所需字段，则不能据此形成总体结论。

### sample_table_data

- 样本只用于理解字段形式、典型取值或数据形态，不能代表总体比例、完整范围、分布或普遍规律。
- 检查 `sample_limit`、`returned_rows`、`truncated` 和 `excluded_columns`。
- 样本中没有出现某种值，不代表总体中不存在该值。

### 敏感字段

- 字段可能被完全排除，或其值被替换为 `[已脱敏]`。报告不得猜测、还原或暗示原始值。
- 被排除或脱敏的数据不能作为需要原始值的分析证据；必要时说明隐私保护导致的可见性限制。

### describe_table

- 检查 `metadata_warnings`。外键、索引等元数据不可用时，应表述为“当前无法确认”，不能表述为“不存在”。
- 字段名称和类型不等于业务定义。没有字段注释或业务说明时，不根据名称臆测单位、含义或业务规则。

## 工作流程

### 1. 确认报告对象和目的

确认报告要回答的问题、目标读者、读者需要做出的决策、详细程度和格式要求。面向管理者时优先呈现影响和行动；面向分析人员时可保留更多方法、口径和质量细节。

### 2. 盘点证据并判断可交付程度

整理分析目标、数据来源、范围、指标定义、数据质量说明、核心数字、发现、图表数据、限制和已有建议。检查 Tool Result 是否完整，以及关键结论是否有对应证据。根据材料状态决定生成正式报告、初步报告或先请求补充分析。

### 3. 选择报告类型和结构

根据任务复杂度和读者需求选择合适的报告形式与章节。简单问题直接回答；正式报告才使用完整结构。不得为了展示完整性重复内容或增加空泛章节。

### 4. 建立报告主线

围绕用户问题组织材料：分析了什么、数据表明什么、最重要的变化或差异是什么、其业务影响是什么、建议采取什么行动、结论有哪些限制。只保留支持主线的指标和图表。

### 5. 撰写执行摘要

需要执行摘要时，用简洁段落或要点说明分析问题、最重要的两到五项发现、业务含义、建议行动和主要限制。摘要中的数字必须与正文一致，不能引入正文没有证据支持的新结论。

### 6. 呈现指标和发现

关键指标注明数值、单位、时间范围、对比基准、筛选范围和必要口径。每项发现使用能表达实际结果的标题，并组织其证据、解释、影响和限制。基数很小时，明确提醒百分比可能放大观感。

### 7. 规划图表和表格

只为能够改善理解的问题设计图表。先确认图表问题、数据是否完整和统计口径，再选择图表类型并写出规格。精确数值查阅优先使用表格。

### 8. 撰写业务建议

每条建议说明要采取的行动、关联的分析证据、适用范围、优先级和后续观察指标。建议应与发现直接对应。无法确定原因时，优先建议补充分析或验证假设；不承诺没有数据支持的收益。

### 9. 保留限制并校验一致性

写明会影响解读的数据范围、完整性、统计口径、缺失、样本量、截断、脱敏和方法限制。输出前核对摘要、正文、表格和图表中的数字与口径。

以上步骤按任务需要使用，不要求简单摘要机械执行全部流程。

## 图表选择与规格

### 选择原则

- 有序时间变化通常使用折线图，并明确时间范围和时间粒度。
- 类别比较优先使用条形图；类别名称较长时可使用水平条形图。
- 构成及其随时间变化可使用堆叠条形图或面积图，但必须明确分母和总量变化。
- 分布可使用直方图、箱线图或分位数表，但样本数据不能用于描述总体分布。
- 两个数值变量的关系可使用散点图；只能描述关联，不能仅凭图形推断因果。
- 精确数值、详细排名或查阅型内容优先使用表格。
- 类别较多时避免使用饼图；不滥用双轴图，不使用 3D 图制造视觉差异。
- 数值轴原则上保留合理基线。若为突出细微变化而截断坐标，必须明确标注，不能夸大差异。

### 图表规划内容

没有图表 Tool 或用户只要求规划时，每个建议图表应尽可能说明：

- 图表标题和需要回答的具体问题。
- 图表类型。
- 使用的数据字段和统计口径。
- 横轴、纵轴、单位和必要的图例。
- 时间范围和时间粒度。
- 排序方式，以及 Top N、其余类别或并列值的处理方式。
- 缺失值、未知类别和异常值的处理方式。
- 百分比的分母。
- 图表数据是否完整，是否受到行数、结果大小、字段长度、样本或筛选限制。
- 图表需要表达的、已经由数据支持的发现。

图表结论必须与实际数据、表格和正文一致。没有实际生成图表时，明确标注为“建议图表”或“图表规格”，不得声称已经生成图像。

## 数据依据与追溯

对影响核心结论的重要指标，应保留足以复核的信息，例如数据来源、统计对象、时间范围、筛选条件、聚合维度和关键口径。可以在“数据与方法”、指标注释、表格说明或附录中呈现，不要求把所有 SQL 放入正文。

如果用户需要审计，可以附上实际执行的 SQL、Tool Result 摘要或查询说明；没有此要求时，优先保持正文可读。不得把未执行的 SQL 或规划中的计算描述为实际数据来源。

## Markdown 输出建议

根据报告类型选用结构，不要求所有报告使用同一模板。

### 简短结果摘要

```markdown
## 结果

直接回答问题并给出关键数字。

> 统计口径或重要限制
```

### 管理层简报

```markdown
# 简报标题

## 核心结论
## 关键发现
## 建议行动
## 主要风险与限制
```

### 正式数据分析报告

```markdown
# 报告标题

> 分析目的、数据范围与时间范围

## 执行摘要
## 分析目标与口径
## 数据来源与方法
## 关键指标
## 核心发现
## 分项分析
## 图表与表格
## 业务建议
## 风险与限制
## 后续分析
```

按实际任务增删章节。对比、趋势和探索性报告可以从以上结构中选择相关部分，不堆砌指标，也不重复解释同一结论。

## 输出要求

交付与任务复杂度相称的 Markdown 内容。重要结论排序清楚，关键数字可追溯，报告状态与材料完整程度一致。图表在有工具并实际生成时才能称为已生成；否则输出明确的图表规划。数据不足、结果截断或存在未验证假设时，在报告中直接说明。

## 质量检查

### 证据与边界

- 报告回答了用户的问题，并服务于目标读者和使用场景。
- 关键数字和事实性结论均有真实 Tool Result、用户数据或已完成分析支持。
- 未重新承担指标计算、质量分析或新洞察发现；缺少关键证据时已指出具体缺口。
- 事实、观察、解释、假设和建议没有混为一谈，相关关系没有被写成因果关系。
- 数据来源、统计范围、单位、时间和关键口径足以理解结论。
- 已正确处理样本、截断、脱敏和元数据警告，没有扩大结果适用范围。

### 数字一致性

- 分类数量之和与已知总体数量一致；不一致时不自行修改数字，而是说明差异并请求核验。
- 百分比的分母明确，比例与绝对数量相容，合计在舍入误差范围内合理。
- 排名顺序与实际数值一致，并列值和 Top N 口径明确。
- 同比、环比使用了正确基期，时间范围和粒度一致。
- 同一指标在摘要、正文、表格和图表中的单位一致。
- 小数位、百分比和舍入规则统一；舍入没有改变结论。
- 执行摘要中的数字与正文一致。
- Markdown 表格和图表规划与原始结果一致，没有漏掉影响结论的行或类别。

### 表达与交付

- 报告结构与任务复杂度相称，简单问题没有被扩写成不必要的长篇报告。
- 执行摘要优先呈现结论、影响和行动，不按分析步骤流水账叙述。
- 图表类型、数据字段、统计口径、轴、单位和数据完整性说明充分，且不造成误读。
- 建议与发现有明确证据链，没有承诺未经验证的收益。
- 没有伪造数据、工具执行、图表生成、文件导出或保存状态。
